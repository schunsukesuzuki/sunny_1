# v0.17 — Automatic public-evidence RAG in step 10

## Summary

The previous v0.16 workflow **did not execute step 00**; it only linked an existing RAG ID, and then reported `00_evidence_grounded_requirements COMPLETED / No external evidence linked; synthetic-demo mode`. This is no longer the default or the behavior of public mode.

Two **explicit** modes are available from the step-10 form:

- `public` (UI default): obtain the selected fixed-source public dataset if absent; verify source files against stored SHA256 when already present; build or validate the index; retrieve excerpts and optionally ask Qwen for draft hypotheses; **pause at 00b for a human review**. The user chooses evidence IDs and writes/edits the hypothesis. Only after approval is the hypothesis appended to the 01 customer brief (with `UNVERIFIED` and `NOT CUSTOMER APPROVED` labels) and 01–04 executed. Step 05 still requires a **different explicit** human decision about the R0→R1 change. Approval continues 06–09. All generated artifacts, reports, logs and metadata are saved to one ZIP.
- `synthetic` (explicitly selected): skip 00 and 00b with `SKIPPED_BY_USER`, execute 01–09 as before, and label results as synthetic. A synthetic success **never** masquerades as successful data ingestion.

**No silent fallback** is permitted. A public network failure, corrupt or changed cached source, empty search, or model extraction failure gives step 00 `FAILED`, workflow `PARTIAL` and a downloadable ZIP with failure reason; it does not continue to 01. A rejected 00b hypothesis likewise stops and exports a PARTIAL ZIP. If you want synthetic-only, choose it and start a new workflow explicitly.

## Step 10 operating instructions

1. In step 00, select **Community Credit** (30 interview transcripts) or **CFPB public complaint sample** and write a query. The separate dataset download button remains available. Step 00's manual operations are optional for batch mode: step 10 will acquire and index automatically.
2. In step 10, select **public** and click **公開データ取得から00〜09一括実行**. Polling shows `RUNNING` and will stop at `AWAITING_EVIDENCE_REVIEW` after successful retrieval.
3. Inspect quoted evidence and select at least one *actual evidence ID* from the **current workflow**, write a human-approved *hypothesis for demo evaluation* (minimum 20 characters), and provide the reviewing actor and rationale. If optional Qwen extraction was enabled, a candidate can be copied into the editable field; it is never automatically approved. Reject if the data is insufficient.
4. After explicit approval, the selected hypothesis and source IDs are recorded in `01_input.json`, then 01–04 run, pausing at `AWAITING_APPROVAL` in step 05.
5. After the usual separate human technical approval, 06–09 run. Download `claims_full_run_v017_<workflow-id>.zip` from step 10. Both interim and final ZIPs include `manifest.json` and raw-byte SHA256 for every included output.

```
  07_history_snapshot.json
...
artifacts/exports/<export-id>/
  complete_audit_package.zip

```

The full-run ZIP includes the workflow snapshots and corresponding `runs/`, `proposals/`, `approvals/`, `experiments/`, `benchmarks/`, `policy_validations/`, and `assessments/` records. The **full raw dataset is separately downloadable** through step 00 as `financial_dataset_<id>_v017.zip`; its entire contents are not embedded into every full-run ZIP. This avoids unnecessary repetition and puts source provenance (file hashes and retrieval location) next to the extracted evidence.

The old `/api/evidence/download`, `/api/evidence/index`, `/api/evidence/requirements`, and `/api/evidence/datasets/{dataset_id}/download` remain. The new v0.17 batch endpoints are:

```text
POST /api/full-run/start
  {"evidence_mode":"public", "dataset_id":"community_credit", "evidence_query":"bank account fees",
   "llm_extraction":false, "brief":"<customer brief>", "seed":42, "evidence_condition":"counterexample"}
POST /api/full-run/review-evidence
  {"workflow_id":"<workflow-id>", "decision":"approved", "actor":"Reviewer",
   "rationale":"Reason to test this hypothesis", "evidence_ids":["PUB-001"],
   "approved_requirement":"Human-edited and still unverified requirement hypothesis"}
POST /api/full-run/approve-and-continue
  {"workflow_id":"<workflow-id>", "approval":{...existing step-05 request...}}
GET  /api/full-run/<workflow-id>
GET  /api/full-run/<workflow-id>/bundle
```

For `synthetic`, `evidence_mode` must be explicitly set to `synthetic`. The API intentionally rejects requests without the mode instead of assuming synthetic success.

## Limits and quality gates

- **Citation pointer accuracy ≠ source validity ≠ semantic entailment ≠ business validity ≠ legal approval.** A real transcript is not evidence that FIFO causes insurance-claims delays. The selected requirement is appended only as a *human-reviewed hypothesis*, not as a certified customer requirement.
- Existing R0 FIFO and R1 fixed synthetic allocation contracts are unchanged. Arbitrary retrieved requirements cannot yet be compiled into new independent allocation verifiers, nor can the app claim they have been fully tested. The code remains a claims-allocation demo.
- Community Credit: real anonymized consumer interviews; not a representative InsurTech customer survey. CFPB: historical complaint *metadata*, which may now lack narratives; the API-derived text is marked `NORMALIZED_API_RECORD`, not a verbatim source span. Source-level evidence is limited and may be irrelevant to the hypothetical insurance client.
- The retrieval is **lexical BM25 + character n-gram RRF**, not dense neural embeddings or semantic RAG. No entailment metric or real customer acceptance is claimed.
- Runs are asynchronous via FastAPI `BackgroundTasks`; polling and saved Workflow IDs support UI reload, but this is not a production durable queue. There is no tenant authentication or external-facing access control.
- Public source availability, redirects and live Ollama/E2B behavior depend on the user's deployment. Offline tests use fixed corpus and mocks; live fetch and frontend production build were not independently verified in this environment.
