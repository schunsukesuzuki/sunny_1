# v0.32 — 技術提案の出典分離・部分修復・COMPLETE同期

## 対象範囲

v0.31実行証跡の10P生成失敗を受け、優先度「高」の3点のみを実装する。

1. **公開根拠IDはプログラム側で固定**。`00b_human_evidence_review.json` から選定済みの `PUB-*` とURL・抜粋を読み、`10p_advisory_vNNNN.json` の `deterministic_public_context` に保存する。内容は「公開文脈」であり、顧客固有の問題の証明ではない。LLMに生成させる `customer_problem_hypotheses` は `statement` と `unknowns` に限定し、保存時に `hypothesis_unverified` / 空の `source_refs` を確定する。出典IDの対応の有無と、内容が仮説を支持するかは別問題。
2. **不適合セクションのみ修復**。初回のLLMが型付き応答を返した後、要件ID・通知の直接カバー・コスト見積の捏造・実験出典・日本語などを独立検査。意味的に不適合なトップレベルセクションだけを別スキーマで最大1回再生成する。変更しなかったセクションを維持し、再検査で失敗なら全体提案は `GENERATION_FAILED`。モデルがJSON/型スキーマの初回パースに失敗する場合の汎用復旧は含めない。成功時は `repair_actions` に修復セクションと変更前後のハッシュを記録。モデルは審査や根拠の真偽を最終判定しない。
3. **最新COMPLETEに同期**。10Rの自動提案開始はワークフロー `COMPLETE` のみに制限。`PARTIAL` 中の提案は画面でユーザーが暫定モードを選択し、APIでも `provisional_mode=true` を要求する。生成中または生成後に08/09等が更新された場合は保存済みハッシュ照合で `STALE_ADVISORY`。旧版は履歴として残り、人間レビュー前に明示的な再生成が必要。

## 手動動作確認

- `docker compose build --no-cache api web && docker compose up -d --force-recreate`
- 公開データモードで完了した後、10Rの**最初**にAI技術提案、その後に00〜09の評価結果が見えること。
- 10Pの出典一覧には選定済み`PUB-*`が表示され、顧客課題仮説には出典による裏付けを自動付与しないこと。
- `PARTIAL`時、チェックを入れない限り提案生成ボタンが押せず、直接APIでも409になること。
- 提案が参照する評価を変更した後、`STALE_ADVISORY`が表示され、旧提案レビューを拒否すること。
- Qwenが出典のIDをうまく返せなかっただけで生成全体が落ちることはなく、意味的に不適合なセクションは1回限りの修復を試すこと。

## 非対象・制限

- 自動CI/CD、自動再実行、実顧客の受入、モデルの真偽判定、モデルが出した全RAWの保存、すべての型/パースエラーからの自動修復は実装しない。
- `COMPLETE`は処理の完了であり、診断HOLDや09のNO-GOを覆さない。
- 研究用アプリであり、商用の本人認証・データ保護・法令保証の代替ではない。
