# v0.8 Input / Output / Independent evaluation contract

## input.json

```json
{
  "schema_version":"claims-0.8", "seed":42,"days":4,"currency":"EUR",
  "reviewers":[{"reviewer_id":"R-A","skills":["motor","property"],"daily_capacity_hours":[5,5,5,5]}],
  "cases":[{"case_id":"C001","arrival_order":1,"required_skill":"motor","duration_hours":3,"deadline_day":3,"amount_eur":12500,"business_priority":2}]
}
```

`cases` are a backlog snapshot. Day 0 is earliest planning day. Day 0 deadline means complete on day 0. Claim duration is modeled as an indivisible integer-hour block within one day (no partial work or hand-offs). Reviewers may take multiple claims/day up to the stated capacity and must possess the required skill.

## output.json

```json
{
  "assignments":[{"case_id":"C001","reviewer_id":"R-A","day":0,"hours":3}],
  "unassigned_case_ids":[]
}
```

Every claim must be either assigned exactly once or explicitly unassigned. Unassigned and delayed claims count as missed deadlines. Over-capacity, wrong skills, duplicated claim IDs, missing claims, noninteger day/hours, wrong durations, unknown IDs are all invalid regardless of their KPI.

## Independent fixed evaluator

`backend/app/domain.py:validate` is *not* generated by Qwen. R0 checks equality to the deterministic FIFO reference assignment. R1 permits alternative schedules but checks the same qualification, duration and capacity invariants. The fixed metric is missed deadline count and actual hours, not a self-reported reward. Generated code is run only in the E2B Sandbox (internet off). The exact reference is **not a mathematical optimal solver**.

## Application ports

`localhost:5173` frontend, `localhost:18000` backend (default). Docker-internal API is `api:8000`.
