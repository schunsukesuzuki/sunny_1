# EU InsurTech / Claims Operations Planner — 顧客仮説（設計のみ）

> 架空の欧州InsurTech企業を想定。顧客実績、マーケット需要、金融・保険規制適合、実運用可能性について何も証明していません。**教育SaaS向けE2B実験のデータを保険業務の検証として流用しないこと。**

## 顧客・事業仮説

- 顧客：ドイツを起点に複数EU国へ展開しようとする保険業務SaaS企業（仮想）。
- 主な意思決定者：Claims Operations責任者、プロダクト責任者、コンプライアンス責任者。
- 課題仮説：審査案件の複雑度、期限、担当資格、稼働時間が異なり、人手による割当が遅延や負荷集中を生む。
- MVP：**支払可否をAIで判断せず**、人間による審査作業の割当候補のみを提案・比較する。
- 主要KPI候補：期限超過件数、担当者ごとの作業負荷ばらつき、割当調整所要時間、監督者の手動修正頻度。
- 必須の人的介入：配分プランの確定・例外処理は人間が承認する。

## 想定サービス設計

| 項目 | 仮説 |
|---|---|
| Actors | Claims Manager, Reviewer, Compliance Officer |
| Entities | Claim, Reviewer, Qualification, Shift, Assignment, AuditEvent |
| Use cases | 新規案件登録、担当者割当案の提示、期限超過リスクの確認、手動再配分 |
| Hard constraints | 資格適合、担当者時間上限、審査作業の重複割当防止、期限と業務時間の整合 |
| Soft objectives | 期限超過最小化、割当公平性、監督者調整工数の低減 |
| Inputs | 案件の必要スキル、所要時間見積、処理期限、担当者の資格と勤務スケジュール |
| Outputs | 候補割当、制約違反・充足不能の理由、代替案、監査履歴 |
| Alternatives | 先着順、技能適合Greedy、混合整数計画、Qwenによるヒューリスティック提案 |

## 実装・検証に向けて必要な追加開発

1. 新しい合成`claims`/`reviewers`データスキーマと実行I/O契約。
2. スケジューリング問題としての妥当な整数計画定式化（資格、利用可能シフト、期限など）。
3. **教育デモとは別の独立評価器**：二重割当、資格違反、時間違反、期限違反、充足不能ケースを検査。
4. 先着順/ルールベースと実行可能な厳密最適化の比較（OR-Tools等を使う場合は実行環境・依存も設計）。
5. 実業務に即したベースラインと顧客由来の業務KPI。顧客に提供する意思決定支援システムとしての規制、個人情報・DPA・GDPR等の検討。
6. 合成ベンチマーク上の性能と実際の顧客価値を分けた評価。実顧客での観測なしに`SUPPORTED`/`GO`を出さない。
